Where this won't help

Cases we're the wrong tool for.

✕A PDF that's mostly text. There's little to squeeze — expect a few percent, not 70.
✕Files over 500 MB on a phone. The tab runs out of memory. Use a desktop.
✕Print-shop preflight. You want Acrobat Pro — we don't do PDF/X colour conversion.
✕Hitting an exact size. Use Compress to a size instead.

Everything we've changed →

1Live upload counter

A PerformanceObserver on resource entries, filtered to requests carrying file data. Real number, updating as you work. Nobody else can print this because theirs wouldn't be zero.

~½ day · every on-device tool

2Proof at the result

The counter graduates from a quiet chip to the headline the moment there's a result to be proud of. This is where the privacy claim is most persuasive — it just happened.

shares the counter's code

3Keep going

Reuses lib/file-handoff.ts, already written for the PDF viewer. Free tools carry the file; Pro chips route without it so a gated click can't strand a stale file.

~1 day · raises tools-per-visit

Numbers come from the benchmark log we already keep. Only ships on tools where we've actually re-measured, with the date visible. A stale benchmark is worse than none.

~1 day + re-testing

Build order

Sequenced by return per hour, not by page order. The first two are nearly free and touch every tool in the catalogue.

What changes in code

All seven are additive props on the shared tool-page template, so a tool opts in by adding data to the catalogue — no per-page work. Rough shape: lastImproved (derived, no input), handoff, fileEffects[], limits[], benchmark. Tools that pass nothing render exactly as they do today.

The JSON-LD already on these pages gains nothing automatically — but the where it won't help and what this does copy is genuinely new indexable text on 67 pages, which is the kind of depth thin competitor pages don't have.

Two things to get right

The counter must never lie. If a tool falls back to the server path — Office conversions, OCR, anything AI — the block has to say so plainly rather than quietly disappear. A privacy claim that's wrong once costs more than all six blocks earn.

Benchmarks need a date and a re-test. Rivals ship changes too. Any figure on a live page gets re-measured before it goes up, and carries the date it was taken — otherwise the most trust-building block on the page becomes the most damaging.
