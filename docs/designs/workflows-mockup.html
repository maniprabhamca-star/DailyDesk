What it is, and why it’s ours

The moat

On-device chaining

Because every step runs in your browser, one tool hands the file to the next with zero re-upload. Server tools (iLovePDF, Smallpdf) must send your file up and pull it down at every step — they can’t chain seamlessly, and they can’t promise privacy through the chain. We can.

Reuses what exists

Not new engines

It orchestrates the tools you already have, headlessly:

  • the same compress / merge / sign / redact-clean engines
  • the batch-runner for multi-file
  • the file-handoff store for passing files between steps

So it’s mostly a builder UI + a sequencer, not fresh algorithms.

Gating

Pro — dark until launch

Ships coming_soon (owner-only) like the AI suite, so you can use it now and it stays hidden from the public until Pro launch. Free users see it in the catalog with a Pro badge and land on the pricing page.

How it maps to your existing promise

Your copy already sells this — “one-click document assembly line — merge · clean · sign · share-safe · compress” on /overview, a Pro line on /pricing, and the client-packet-builder is the static, click-each-step precursor. This turns that promise into a real, running pipeline: define once, drop, done.

Scope for v1: on-device PDF steps only (the list in the palette), sequential run, per-step progress, single output (or a zip for batch). Saved locally on-device; synced across devices is a fast-follow once accounts carry it.

Free vs Pro line

To match how you gate scale, not quality: a couple of built-in templates could run free on a single file (a taste), while saving your own workflows + batch + more than N steps is Pro. Final call is yours — the mockup shows everything as Pro since that’s the launch plan.
